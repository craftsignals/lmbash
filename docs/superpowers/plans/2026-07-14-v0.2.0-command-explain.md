# v0.2.0 Command Explain Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add LLM-backed medium/high-risk notices and two-level command explanations without changing existing execution confirmation behavior.

**Architecture:** Provider clients gain a text-analysis request path that preserves multi-line responses while command generation retains command cleanup. The CLI owns one current command and explanation state, requesting risk, brief, or detailed analysis with the configured client.

**Tech Stack:** Python 3.9+, standard-library `unittest`, existing OpenAI-compatible and Claude-compatible HTTP clients.

## Global Constraints

- Keep `y` and `yes` as the only execution confirmations; risk assessment is display-only.
- Reuse the existing provider, model, proxy, and credentials; add no configuration keys or dependencies.
- Show no notice for `low`; show a one-line notice only for `medium` and `high`.
- `x` always requests a brief explanation; `xx` is available only after a successful brief explanation for the current command.
- Editing resets explanation state and triggers a fresh risk assessment.
- Do not add local risk rules, a result cache, or a command database.

```python
def parse_risk_assessment(response):
    lines = response.splitlines()
    if not lines:
        return None
    level = lines[0].strip().lower()
    reason = " ".join(line.strip() for line in lines[1:] if line.strip())
    if level not in {"low", "medium", "high"} or not reason:
        return None
    return level, reason
```

`build_risk_prompt` must require exact first-line values `low`, `medium`, or `high`, followed by one concise reason. `build_explanation_prompt` must delimit the command and ask for either three concise sections or a shell-structure walkthrough. Both prompts must prohibit executing, modifying, or regenerating the command.

```python
def choose_action(explain_more_available, stream=None):
    suffix = ", [xx] explain more" if explain_more_available else ""
    message = f"Action? [y] execute, [e] edit, [x] explain{suffix}, [N] cancel "
    if stream is None:
        answer = input(terminal.action(message)).strip().lower()
    else:
        print(terminal.action(message, stream), end="", file=stream, flush=True)
        answer = input().strip().lower()
    if answer in {"y", "yes"}:
        return "execute"
    if answer in {"e", "edit"}:
        return "edit"
    if answer == "x":
        return "explain"
    if answer == "xx" and explain_more_available:
        return "explain-more"
    return "cancel"
```

Generate a command once, request and render its risk assessment, then enter an inner action loop. `x` requests `build_explanation_prompt(command, "brief")` and only then sets `brief_explanation_seen = True`; `xx` requests the detailed prompt only when that state is true. `e` exits the inner loop, gets the edit request, generates a replacement, resets state, and repeats risk assessment. `y` retains the existing `--print-command` and `run_command` branches. Render only medium/high results with `terminal.risk_notice`; malformed or failed risk assessment displays a non-blocking unavailable notice. Any `LmBashError` from explanation prints an error and leaves the inner loop active.
